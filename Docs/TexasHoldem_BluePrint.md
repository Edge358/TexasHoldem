## Game Wiring (WPF)

### Start/Run Flow

- `NextHandButton` starts the game on first click (label "Start Game"), then becomes "Next Hand".
- Game starts on a background task.
- Player list (8 seats):
  - Seat 1: Smart (Rock)
  - Seat 2: Smart (Nit)
  - Seat 3: Smart (WeakTight)
  - Seat 4: Human
  - Seat 5: Smart (CallingStation)
  - Seat 6: Smart (TAG)
  - Seat 7: Smart (LAG)
  - Seat 8: Smart (AggroFish)

Display names are fixed (not the raw player names):
- `Player{seatIndex} {ArchetypeAbbrev}` for Smart (e.g., `Rock`, `Nit`, `TAG`, `LAG`, `CS`, `WT`, `AF`)
- `Player{seatIndex} H` for human

### Seat Archetype Selection

- Right-click any seat name between hands to choose an archetype.
- Menu shows a checked item for the current archetype.
- Changes apply between hands (during the pause).

### Human Input

- Implemented by `WpfHumanPlayer` which uses `IHumanPlayerController`.
- UI controls in bottom bar:
  - Fold (left), Check/Call (left), pot shortcuts (1/3, 1/2, 2/3, POT, 1.5X, 2X, 3X), All-In, Check/Call (right), Fold (right), Next Hand
  - Raise button and Raise amount textbox are present in XAML but currently hidden (Collapsed)
- Actions are routed through a `TaskCompletionSource<PlayerAction>` and block until the user clicks.
- Fold button behavior: checks when nothing to call; folds otherwise. During hand pause it advances to next hand.

### Seat/Card Updates

`WpfUiDecorator` wraps each player and updates `WpfTableView` on game events:

- `StartHand`
  - Waits for Next Hand pause (see below)
  - Sets cards, stack, status, clears folded/winner state
  - Resets per-hand contribution
  - Updates buy-in counter (human only)
- `StartRound`
  - Updates community cards + pot
- `PostingBlind`
  - Updates pot + stack
  - Updates bet total with last contribution
- `GetTurn`
  - Updates pot, stack, status, log
  - Updates bet total and folded state
  - On the human’s turn, refreshes the AI recommendation panel
- `EndHand`
  - Highlights winners
  - Calculates net change from `EndStacks` and displays in status (`Winner +X` or `-Y`)
  - Logs showdown, board, pot total, winners, and per-seat Net/Inv lines
  - For the human player, AI panel switches to end-of-hand summary
  - Requests hand pause

Bet slot prefixes:
- `SB`, `BB` for blinds
- `B` (bet), `R` (raise), `RR` (re-raise)
- `C` (call), `X` (check), `F` (fold)
- Prefix spacing uses extra spaces for readability.

### Next Hand Pause Logic

- `NextHandButton` pauses the game between hands for review.
- `NextHandButton` behavior:
  - During player turn: folds immediately and skips pause
  - Outside turn: sets skip-pause flag so next pause is skipped
- `NextHandButton` highlights cyan only during end-of-hand pause.
- Actual pause happens at the start of the next hand before cards are dealt.

Control flow:
- `EndHand` -> `RequestHandPause()`
- `StartHand` -> `WaitForNextHand()` (blocks only if pause pending)

This ensures all players finish EndHand (winner highlighting) before pausing.

### Decision Flow (Heuristic Summary)
### Decision Log Format

SmartPlayer appends a single line per decision to `ai_decisions.log` in the app working directory:

`HH:mm:ss | SeatX | Archetype | Skill | Street | Pot | ToCall | HeroStack | Action | Amount | BB | CurrentMaxBet | MinRaiseTo | CanRaise | SPR | IsHeadsUp | NumPlayersActive | BoardTexture | MadeHand | Draw | RaiseTo | PreflopTier | PreflopStrength | RaiseDepth | CommitFrac | Commit | ThinValue | ValueCBet | DelayedValueCBet`

Notes:
- `Amount` is raise-by amount (increment after calling).
- `RaiseTo` is `CurrentMaxBet + Amount` (or `Amount` if `ToCall==0`), otherwise `-`.
- `CommitFrac` is `(ToCall + RaiseBy) / HeroStack` for raises; `Commit` is chips committed.
- `ThinValue`, `ValueCBet`, `DelayedValueCBet` are 1/0 flags.

### Engine Semantics That Affect AI

- Pot: sum of chips already in the pot; excludes the acting player’s pending call.
- Raise semantics: `PlayerAction.Raise` is raise-by after calling (total bet becomes `CurrentMaxBet + RaiseBy`).
- `MoneyToCall`: `CurrentMaxBet - MyMoneyInTheRound` (capped by stack).

### Preflop Gates & Menus

Preflop strength tiers (from `HandStrengthValuation.PreFlop`):
- Premium: >= 3000
- Strong: >= 2000
- Medium: >= 1000
- Weak: < 1000

Preflop raise depth (based on `CurrentMaxBet / BB`):
- 0: <= 2bb (unopened)
- 1: <= 6bb (open)
- 2: <= 15bb (3-bet)
- 3: <= 35bb (4-bet)
- 4: > 35bb (5-bet+)

Preflop hard gates (summary):
- Tight profiles fold weak hands; additional fold thresholds at 6bb/10bb calls.
- Raise depth >= 3 (facing 4-bet+): only Premium can raise (Maniac exempt).
- Raise permission gates on Weak/Medium tiers to reduce 3-bets; LAG/Maniac are the only archetypes with exceptions.

Preflop sizing menu (raise-by semantics):
- Unopened (`CurrentMaxBet == BB`):
  - Rock/Nit/WeakTight: 2.5bb only
  - TAG/Reg/CallingStation/AggroFish: 3bb only
  - LAG: 3bb, 4bb
  - Maniac: 4bb, 6bb
- Facing open (`CurrentMaxBet > BB`): one 3-bet size only
  - Rock/Nit/WeakTight: 3x open
  - TAG/Reg: 3.5x open
  - LAG: 4x open
  - Maniac: 5x open

Preflop all-in candidate gating:
- Only added if:
  - HeroStackBB <= 25 AND PreflopTier >= Strong, OR
  - ToCallBB >= 12 AND PreflopTier == Premium, OR
  - Maniac AND (ToCallBB >= 6 OR HeroStackBB <= 40) AND PreflopTier >= Strong
- Commitment gate (see below) can still remove oversized raises.

### Postflop Menus & Gates

Postflop bet sizes when `ToCall==0`:
- Rock/Nit/WeakTight: 33%, 50%
- TAG/Reg: 33%, 66%
- CallingStation/AggroFish: 33%, 50%
- LAG: 50%, 75%
- Maniac: 33%, 50%, 75%, 100%
(All sizes capped by potCap; all-in only added if postflop all-in gating allows.)

Postflop raise sizes when `ToCall>0`:
- Non-Maniac: MinRaise and 0.75 * potCap (if valid)
- Maniac: wider raise menu (min + capped larger size)

Postflop all-in candidate gating:
- Allowed if:
  - MadeHandClass == Monster, OR
  - Maniac always, OR
  - SPR <= 3 AND (LAG/Maniac) AND (Strong+ or Combo), OR
  - SPR <= 2 AND AggroFish with Combo on non-Dry

Postflop raise escalation control (street raise depth):
- Depth 0: no bet yet (ToCall==0 and CurrentMaxBet==0)
- Depth 1: facing bet (ToCall==CurrentMaxBet)
- Depth 2: facing raise (ToCall < CurrentMaxBet)
- Depth 3: depth==2 AND MinRaiseTo >= 1.5 * CurrentMaxBet

Escalation gates:
- Depth >= 3: raise only with Monster or Strong+Combo (non-Dry). Rarity: TAG/Reg 10%, LAG/AggroFish 20%, Maniac 30%, tight profiles only Monster.
- Depth == 2: Gutshot/TwoOver never raise. OESD/FD only LAG/Maniac on SemiWet/Wet with low frequency. Combo draws: LAG 25%, TAG/Reg 15%, Maniac 35%.

River raise restrictions:
- Air: only LAG (15% roll) or Maniac; others never raise.
- AggroFish: no raises with Weak/Medium on river unless Strong+ or Combo.

### Commitment Gate (Stack Commitment Filter)

Applied after candidate generation:
- If commitFrac >= 0.70:
  - Preflop: only Premium (or Maniac Strong+ with HeroStackBB <= 30) may keep the raise.
  - Postflop: only Monster, or Strong+Combo (LAG/Maniac, non-Dry), or SPR <= 1.
- If commitFrac >= 0.85 and NOT Maniac: require Monster or SPR <= 1.

### Pot-Odds Defense Floor

Applied after candidate generation (before scoring):
- Strong/Monster: if `ToCall / (Pot + ToCall) <= 0.30`, remove Fold candidate (unless SPR <= 0.5).
- Medium: if `ToCall / (Pot + ToCall) <= 0.15`, remove Fold candidate (unless SPR <= 0.5).

### Value/Thin Value Betting

Thin value bet (33% pot) rules:
- Flop/Turn, `ToCall==0`, `CanRaise==true`, Medium, no draw, <=3 players, non-Wet texture.
- Frequencies: LAG 55, AggroFish 45, Reg 40, TAG 35; -15 on SemiWet.
- If roll fails, remove bet candidates (check only).

ValueCBet (Flop) rules:
- Flop, `ToCall==0`, `CanRaise==true`, preflop aggressor, MadeHand >= Medium, <=3 players.
- Frequencies (Dry/SemiWet): LAG 80, AggroFish 65, Reg 60, TAG 55, Others 30.
- Multiway + Wet: require Strong+ and reduce frequency by 20.
- If roll passes, keep only 33% pot bet.

DelayedValueCBet (Turn) rules:
- Turn, `ToCall==0`, `CanRaise==true`, preflop aggressor, flop checked through, MadeHand >= Medium, <=3 players.
- Frequencies (Dry/SemiWet): LAG 70, AggroFish 55, Reg 55, TAG 45.
- Multiway + Wet: require Strong+ and reduce frequency by 20.
- If roll passes, keep only 45% pot bet.


High-level decision order in `HeuristicDecisionModel`:

- Build `SpotFeatures` (street, pot, stacks, board texture, made/draw class, preflop tier, etc.).
- Preflop hard gates (tier + raise depth) to block trash hands and deep 4-bet+ raises.
- Generate candidate actions (fold/call + raise sizes per street/archetype), with all-in gating.
- Apply thin/value bet filters (33% or 45% pot) when rules fire; otherwise allow normal menu.
- Apply commitment gate to remove raises that effectively play for stacks without strong equity.
- Score remaining candidates and select via weighted softmax (skill-based randomness).
### Decision Model (Heuristic)

SmartPlayer builds `SpotFeatures` from engine context and classifies:
- Made hand class, draw class, board texture via `HandBoardClassifier`
- Preflop strength via `HandStrengthValuation.PreFlop`

Candidate actions are generated with:
- Preflop sizing menus per archetype (fixed opens + 3-bet sizes)
- Postflop sizing menus per archetype (limited pot fractions)
- All-in candidates gated by hand strength, SPR, and archetype

Gating layers include:
- Preflop tier gates (avoid trash hands)
- Raise depth gates (avoid deep preflop 4-bet+ raises without Premium)
- Postflop raise escalation gates (rare 3-bets without strong equity)
- Commitment gate (block raise-by that commits too much stack)
- River raise restrictions for Air/Weak/Medium

### Classifier Notes

- Sets are always `Monster` (pocket pair + board match).
- Flushes: top-flush is `Monster`, lower flush is `Strong`.
- Board straight without improvement is downgraded to `Medium`.

### Cash Game Stack Cap (Engine)

- `TexasHoldem.Logic/GameMechanics/TexasHoldemGame.cs` caps non-human stacks to 200 at start of each hand.



### AI Tuning Checklist

Recommended order when tuning behavior:
- Adjust `PlayerProfile` archetype parameters (tightness/aggression/bluff/risk).
- Tweak preflop tier gates and raise depth gates (avoid trash and deep 4-bet+).
- Adjust sizing menus (preflop opens/3-bets, postflop bet/raise sizes).
- Tune postflop raise escalation gates (street raise depth + rarity).
- Tune commitment gate thresholds for stack-off control.
- Adjust thin/value c-bet frequencies.

### AI Log Field Glossary

Common log fields and intent:
- `RaiseDepth`: preflop raise depth (0=open, 1=open, 2=3-bet, 3=4-bet, 4=5-bet+).
- `CommitFrac`: `(ToCall + RaiseBy) / HeroStack` for raises.
- `Commit`: chips committed by a raise (ToCall + RaiseBy).
- `ThinValue`: 1 when thin value bet rule fired (33% pot).
- `ValueCBet`: 1 when flop value c-bet rule fired (33% pot).
- `DelayedValueCBet`: 1 when turn delayed value c-bet rule fired (45% pot).
- `RaiseTo`: `CurrentMaxBet + RaiseBy` (or `RaiseBy` when `ToCall==0`).

### Heuristic Intent Notes

- Tight profiles should avoid marginal preflop and deep 4-bet+ lines without Premium hands.
- LAG should apply pressure but avoid deep-SPR jams without strong equity.
- AggroFish is loose/aggressive but capped by commitment + all-in gates.
- Multiway pots should reduce bluff frequency and raise escalation.
- River bluffs are heavily restricted; most raises should be value.

## Addendum: Current Final State (UI / Layout / Window Management)

This addendum documents the finalized behavior and architecture reached after the latest
UI/layout iteration. It supplements all prior sections without removing or invalidating them.

### Window Sizing & Startup Behavior
- Main window no longer forces a fixed pixel size.
- On first run (or when persistence is disabled), the window opens at ~85% of the current
  SystemParameters.WorkArea, with sensible min/max clamps.
- Sizing logic executes once at startup and never fights user resizing.

### Window Placement Persistence (User‑Controlled)
- Window size and position persistence is **opt‑in**.
- A small on‑table checkbox labeled **“Save on Exit”** controls persistence.
  - Default: unchecked.
  - When unchecked:
    - No saved placement is restored.
    - No placement is saved on exit.
  - When checked:
    - Width, Height, Left, Top, and WindowState are saved on close.
    - Saved placement is restored on next launch if valid.
- Minimized state is never restored.
- Restored bounds are clamped to the current WorkArea so the window is always reachable.
- Persistence is implemented via user‑scoped application settings.

### Table Layout Model
- The poker table uses a fixed logical design space of **1280 × 720**.
- A Viewbox with `Stretch="Uniform"` scales this space to fit the window.
- Aspect ratio is preserved; letterboxing is expected when window proportions differ.

### On‑Table Overlays (AI & Log)
- AI and Log toggles and panels are part of the **scaled table surface**, not window overlays.
- All on‑table overlays live inside the Viewbox/Canvas tree so they scale with the table.

#### AI Recommendation Panel
- Toggle and panel are inside the table canvas.
- Panel uses fixed design‑space sizing and is positioned in code relative to its toggle.
- Repositions automatically on window resize.

#### Action Log Panel
- Toggle is on the carpet, aligned bottom‑right.
- Log panel expands **upward** from the toggle and grows leftward in width.
- Panel height is dynamic:
  - Clamped to the available space above the toggle.
  - Never extends off the top of the table surface.
- Panel positioning is computed in table‑coordinate space and updates on resize.
- No fixed pixel height; width is fixed in design space.

### Coordinate Transform Notes
- Positioning between sibling visuals inside the Viewbox uses `TransformToVisual(...)`
  rather than `TransformToAncestor(...)` to avoid invalid‑ancestor exceptions.

### Letterbox Background
- The unused area around the scaled table uses a solid carpet‑matching color.
- No stretched table imagery is used behind the Viewbox to avoid seams or table bleed.
- Visual treatment may be revisited later, but current approach is intentional and stable.

  `SmallBlinds` array was removed. Both values are validated to the range 1 to
  200000.
- **Game size presets.** A dropdown at top left offers 1/2, 2/4, 5/10, 10/20,
  50/100, 100/200. Built in `MainWindow.xaml.cs` `InitializeGamePresets` and
  `CreatePreset`. Changes apply to the next game, not mid-hand.
- **Card visibility modes.** A second dropdown offers ALL, Human, and Peek.
  Enum `WpfTableView.CardVisibilityMode`: `ShowAll`, `HumanOnly`,
  `PeekOnHover`. Peek reveals AI hole cards on mouse hover only.
- **Show Raise checkbox.** Hides or shows the seven raise-size buttons.
- **Keyboard hotkeys.** Action buttons carry underlined access keys, applied
  by `ApplyHotkeyLabels` and `CreateUnderlinedContent`.
- **Persisted settings.** `Properties.Settings` now stores game size index,
  card visibility index, Show Raise state, and window placement (opt-in via
  Save on Exit).
